Chapter 02

Agent Anatomy

Every agent in Eigur is not a simple chatbot — it is a fully constructed digital entity with seven core components: Soul, Heartbeat, Memory, Workspace, Tools, Skills, and Voice. Together these make each agent feel real, persistent, and professional.

🔮
SOUL
The agent's identity — who they are, not just what they do. Defined by a system prompt that encodes: name, personality traits, communication style, core expertise, professional values, decision-making tendencies, and relationship to Eigur's mission. Aria is decisive and visionary. Zane is precise and architecture-obsessed. Cypher is vigilant and never trusts by default. Each soul is unique and consistent across all interactions.
Storage: System prompt + character.json per agent
💓
HEARTBEAT
The agent's activity pulse — a periodic trigger that keeps agents alive between tasks. Every agent runs a heartbeat cycle: check for new tasks assigned to them, check for escalations from their team, check if any standing reports are due, check their own memory for anything flagged. Heartbeat frequency varies by role — C-Suite every 30 min, Team Leads every hour, Junior agents every 2 hours (simulated cycles in OpenClaw).
Implementation: Cron-triggered OpenClaw pipelines
🧠
MEMORY
Four-layer memory system (see Chapter 03). Short-term (session), Long-term (personal JSON file), Shared Entity (company knowledge base), Semantic Search (ChromaDB local vectors). Each agent's memory folder at /eigur/agents/[name]/ contains: memory.json, decisions.log, task_history.json, relationships.json (who they've worked with and how). Memory is queried before every task and updated after.
Storage: /eigur/agents/[name]/memory/ directory
🗂️
WORKSPACE
Every agent has a dedicated file system workspace. Like a physical desk — their current task files, WIP documents, reference materials, and scratch notes all live here. When Arjun builds an auth module, his workspace has the spec, his notes, code drafts, and test results. Workspaces are isolated but shared outputs go to the project's shared directory. Workspaces persist between sessions.
Location: /eigur/agents/[name]/workspace/
🔧
TOOLS
Agents are equipped with tools matching their role. Not every agent has all tools — a junior marketer doesn't need a code execution tool. Tools are assigned per role and registered in OpenClaw. Common tools: file_read/write, web_search (for research agents), code_execute (engineering), memory_query, discord_post (for reports), calculator (finance), security_scan (security dept only). Tools are versioned and audited.
Registered in: /eigur/agents/[name]/tools.json
⚡
SKILLS
Skills are pre-built capability modules that an agent can invoke — more abstract than tools. Arjun's skills: API_design, database_schema, code_review, sprint_planning. Anjali's skills: seo_writing, social_copy, content_strategy, brand_voice. Skills are reusable prompt templates + workflows that produce structured outputs. They're like the agent's professional training — instantly accessible institutional knowledge.
Stored as: /eigur/skills/[skill_name].yaml
🎙️
VOICE
Every agent has a defined voice — their way of speaking in meetings, updates, and communications. Voice has three dimensions: Tone (how they carry themselves — Aria is calm authority, Zane is precise engineer, Cypher is watchful analyst), Vocabulary (the words they naturally use — Seema says "from a cost perspective," Lena says "from a user standpoint"), and Meeting Style (how they participate in standups and reviews — some are brief, some thorough, some challenge assumptions). In future phases, voice can be connected to TTS (ElevenLabs, Bark, or Coqui locally) to give each agent a literal audio voice, and a generated avatar for video meetings.
Defined in: soul system prompt + voice_profile.json | Future: TTS + avatar via ElevenLabs + DID.ai

Chapter 03

Memory Systems

Memory is what transforms a stateless language model into a persistent, learning team member. Eigur's four-layer memory architecture ensures agents never forget a decision, never contradict past work, and continuously accumulate institutional knowledge.

L1
SHORT-TERM MEMORY — Session Context
The LLM's active context window during a task. Everything said in the current session — task instructions, intermediate outputs, tool results, partial drafts. Managed automatically. Duration: Single session only. Action on end: Key decisions and outputs are summarised and written to L2.
L2
LONG-TERM MEMORY — Personal Agent Store
Each agent's personal persistent memory. Stored as structured JSON. Contains: task history, decisions made, Chairman preferences learned, errors and corrections, communication patterns. Loaded at the start of every session. Location: /eigur/agents/[name]/memory/long_term.json. Size limit: Last 500 entries, older entries archived.
L3
SHARED ENTITY MEMORY — Company Brain
Company-wide knowledge readable by all agents. Contains: all project specs, ADRs, brand guidelines, tech stack decisions, Chairman directives, past project outcomes, current priorities. Structured as a SQLite database with role-based write permissions. Location: /eigur/company/knowledge_base.db. Updated by department heads after key events.
L4
SEMANTIC SEARCH — RAG Vector Store
When an agent can't find context through structured queries, it semantically searches all memory. "What was the authentication approach we decided for the trading platform?" triggers a vector similarity search across all L2 and L3 data. Engine: ChromaDB local instance. Embeddings: nomic-embed-text via Ollama (free, local). No API cost.

Chapter 04

OpenClaw Integration

OpenClaw is Eigur's orchestration engine — the system that brings the org chart to life. It manages agent pipelines, tool routing, memory I/O, and the OpenClaw → Ollama/Qwen bridge. Understanding how OpenClaw maps to Eigur's structure is essential.

⚙️ What OpenClaw Provides for Eigur
OpenClaw acts as the nervous system of Eigur — it routes tasks between agents, manages the LLM connections (Qwen API for senior agents, local Mistral/Ollama for junior agents), provides the pipeline configuration language, handles tool registration and calling, and manages the conversation context window. Each Eigur agent becomes an OpenClaw pipeline with its own system prompt, tool set, and model assignment.
🔌
LLM Routing in OpenClaw
OpenClaw connects to both Qwen API and Ollama simultaneously. Senior agents (C-Suite + Team Leads) are configured to use Qwen for quality. Junior agents use local Mistral 7B via Ollama to keep costs zero. The model is set per-agent in their OpenClaw pipeline config. Switching a model is one line change.
📋
Agent as Pipeline
In OpenClaw, each Eigur agent is a named pipeline. The pipeline has: system_prompt (soul), model (LLM assignment), tools (registered tools), and a run() function that accepts a task and returns a structured output. Pipelines can call other pipelines — this is how delegation works.
🔀
Task Routing
When the Chairman or Aria assigns a task, OpenClaw's router parses the task type, maps it to the correct department and agent pipeline, loads that agent's memory context, invokes the pipeline, captures output, posts to Discord, and writes to memory. All automated.
💾
Memory Integration
OpenClaw pipelines are wrapped with memory middleware that auto-loads the agent's long-term memory and relevant company KB context before the LLM call, and auto-saves key outputs after. The agent itself doesn't manage memory — the OpenClaw wrapper does it transparently.

OpenClaw Pipeline — How an Agent Run Works

1
Chairman / Aria posts task
A task description is entered in Discord #chairman-desk or #ceo-aria. A Discord bot (running locally, free via discord.py) captures the message and triggers the OpenClaw task router.
2
Task Router identifies pipeline
OpenClaw's router reads the task, uses keyword + context matching to identify the appropriate agent pipeline. If unclear, it routes to Aria (CEO) who then delegates. Routing rules are in /eigur/config/routing_rules.yaml.
3
Memory middleware loads context
The agent's long_term.json is loaded. A semantic search runs against the company knowledge base for relevant project context. Both are injected as context into the agent's system prompt for this session.
4
LLM call executed
The enriched prompt is sent to the assigned LLM (Qwen API or Ollama Mistral). Tools are available for the agent to call during execution. The model runs through the task, may call tools multiple times (plan → execute → self-review loop).
5
Output structured and validated
OpenClaw's output parser validates that the response follows the standard format (Summary / Deliverables / Decisions / Next Steps / Blockers). If missing sections, a brief retry is triggered with the format reminder.
6
Memory updated, Discord posted
Key outputs are written to the agent's long_term.json and relevant items added to the company knowledge base. The formatted output is posted to the appropriate Discord channel via webhook. The task is marked complete in the project tracker.
7
Delegation (if agent is senior)
If Aria or a C-Suite agent received the task, their output includes a delegation plan. OpenClaw reads the delegation and automatically creates sub-tasks for the relevant pipelines. The chain of delegation can go 3 levels deep (C-Suite → Team Lead → Team Member).
Chapter 05

Decision Framework

All decisions in Eigur are classified by tier — this determines autonomy, speed, and who must be involved. The framework prevents both under-delegation (Chairman bottleneck) and over-delegation (agents making critical decisions alone).

Tier Name Who Decides Chairman Required Logged Examples
TIER 4 Micro Junior agents autonomously NO Task log only Library choice, variable naming, file structure
TIER 3 Tactical Dept Head / C-Suite NO — logged Company KB Sprint priorities, API design choices, content strategy
TIER 2 Strategic CEO Aria + affected C-Suite RECOMMENDED ADR document New project launch, major tech pivot, budget >₹50K
TIER 1 Critical Chairman only MANDATORY ADR + Decision Register Company direction, project kill, external contracts
SECURITY Security Override CSO Cypher independently NOTIFIED IMMEDIATELY Security incident log Active breach detected, data exposure, attack in progress
🔐 Security Override Rule The CSO (Cypher) is the only agent who can act without waiting for approval chain confirmation in the case of an active security incident. Cypher can initiate containment protocols, block processes, and alert all agents immediately. Chairman is notified within 60 seconds via Discord @mention. This is the only exception to the hierarchy rule.

Decision Flow Diagram

▶ NEW DECISION POINT REACHED
├── Is this within my defined role?
├── YES → Does it affect other departments?
├── YES → CROSS-DEPT SYNC → Loop in relevant C-Suite → Proceed
└── NO → Classify as Tier 3/4 → Decide → Log → Execute
└── NO → Is this a security incident?
├── YES → CYPHER ACTIVATES SECURITY OVERRIDE → Contain → Alert Chairman
└── NO → Is the decision reversible?
├── YES → Tier 2: Escalate to CEO → CEO decides or brings to Chairman
└── NO → TIER 1: HALT → CEO → CHAIRMAN MANDATORY APPROVAL

Escalation Protocol

1
Agent detects blocker / uncertainty
The agent cannot proceed. It immediately stops, writes a structured escalation: BLOCKER DESCRIPTION / WHAT WAS ATTEMPTED / OPTIONS CONSIDERED / RECOMMENDED RESOLUTION. Does not guess or make out-of-scope decisions.
2
Escalation posted to superior
Escalation is posted in the appropriate channel with a @mention of the direct superior. Discord webhook routes it. If the blocker is time-sensitive (< 2 hour SLA impact), PRIORITY: URGENT is flagged and the superior is @mentioned with 🚨.
3
Superior responds within SLA
Response SLA: C-Suite within 1 hr, Team Leads within 2 hrs, Junior agents within 4 hrs (simulated cycle times). If superior doesn't respond within SLA (their pipeline isn't triggered), escalation automatically goes up one more level.
4
Resolution or Chairman involvement
If escalation reaches CEO Aria unresolved, she makes a decision or brings it to the Chairman as a decision request in the next Executive Brief. Chairman's response is final and binding. All escalation resolutions are logged in memory and the company KB.

🔴 SECURITY DOCTRINE Eigur is an AI company that will handle financial data, user data, and proprietary algorithms. A security breach could be catastrophic — financially, legally, and reputationally. The Security Department operates under a "Zero Trust by Default" model: nothing is assumed safe, every input is validated, every connection is authenticated, every agent action is logged.

Role: Monitors all system logs in real time for anomalies. Tracks failed login attempts, unusual API call patterns, unexpected data access, and agent behaviour anomalies.

Output: Real-time alerts, daily log digest, incident timelines
Model: Mistral 7B (local) — needs to run fast and continuously

Security Policies — Non-Negotiable

🔐
Zero Trust Architecture
Every agent interaction with external systems requires authentication. No agent trusts another agent's output without validation. All API calls are authenticated. Internal service-to-service calls use short-lived tokens. "Trust but verify" is replaced by "Verify, then trust temporarily."
📋
Security Gate on Every Project
No code ships without a security review from Cypher's team. Raze runs automated OWASP scan. Prism checks data handling. Kade confirms logging is in place. All four gates must pass. This is architecturally enforced — OpenClaw pipeline won't trigger deployment without security_approved: true.
🔑
Secrets Management
API keys, database passwords, and credentials are never stored in agent memory or code. All secrets stored in a local secrets manager (HashiCorp Vault or .env with restricted permissions). Cypher audits secrets access monthly. Any leaked secret triggers immediate rotation and incident report.
📊
Audit Logging — Everything
Every agent action is logged: what agent, what action, what input, what output, timestamp. Logs are append-only and stored in /eigur/logs/audit/. Kade monitors these continuously. Any log tampering triggers immediate security alert. Logs retained for 90 days minimum.
⚡
Incident Response Protocol
Detection (0-5 min): Kade alerts Cypher
Triage (5-10 min): Cypher assesses severity
Contain (10-30 min): Raze isolates affected systems
Alert (immediate): Chairman notified
Recover: Patch + restore + post-mortem
🇮🇳
India-Specific Compliance
Prism ensures compliance with: DPDP Act 2023 (Digital Personal Data Protection), SEBI guidelines for trading platforms, RBI data localisation requirements for financial data, IT Act 2000 provisions. All Indian regulations tracked and updated as law evolves.
